# 09 可执行文件与元数据

## 1. XEX2：Xbox 360 可执行文件

`.xex` 是 PE 镜像外面的包装。包装里是主机加载前需要的元数据，PE 镜像跟在后面，压缩并加密。

* 头：`XEX2` 魔数、模块标志、PE 数据偏移、安全信息块偏移、可选头数量。
* 可选头每条 8 字节 `(key, value)`；key 的低字节决定 value 怎么读：`0x00/0x01` 就是数据本身，`0xFF` 是"指向一个首 dword 为大小的块"，其他 n 是"指向 n × 4 字节"。这条规则让整张可选头表即使不认识 key 也能走。
* 安全信息：RSA 签名、镜像标志、装载地址、media id、加密的 AES-128 会话密钥、区域码、允许介质、页描述符数。

### 恢复 PE 的三步

1. **拿到会话密钥**：16 字节，本身是用固定 KEK 做 AES-128-ECB 加密的。零售盘用零售常量，开发机全零。零售常量是公开的（每个模拟器/自制工具链都带，因为主机必须能装载）。
2. **解密**：AES-128-CBC、零 IV，从 `pe_data_offset` 到文件末尾。
3. **解压**：方案由 `FILE_FORMAT_INFO` 指定：0 无、1 basic、2 normal(LZX)、3 delta。

**Basic** 是地址空间的游程描述：一串 `(数据长度, 零长度)` 对，数据从流里拷，零是没存过的空洞；描述在只剩零时停止，所以产物可以比声明的镜像大小短（本作短 32 768 字节），加载器再补零。**Infinite Undiscovery 用的是 basic，两段。**

**Normal 是 LZX**：解密后的主体是一串块，每块开头是**下一块**的大小与 SHA-1；第一块的大小/哈希来自文件格式头；块内压缩字节按 16 位长度分块，零长度收尾；去掉这层框架后是一条 LZX 流。哈希是在解密后对块计算的，因此它能**独立于 LZX 是否说得通**来确认解密正确——这在 normal 方案下尤其重要，因为明文不以 `MZ` 开头。已用另两部 Xbox 360 作品验证：Star Ocean 4 85/85、Resonance of Fate 69/69。

## 2. 本作的 XEX 头

```
image size       : 0xAE0000
load address     : 0x82000000
entry point      : 0x821CBA90
region           : 0x00FF0000  PAL
encryption       : AES-128-CBC
compression      : basic, 2 blocks
original PE name : default.exe
```

* Title ID `0x535107DB`（高半字 ASCII `SQ` = Square Enix）；版本 2，碟 1/2，无存档 id。
* 静态库全部来自同一 SDK：XAPILIB、D3D9、D3DX9、XGRAPHC、XMEDIA、XAUD、XMP、XONLINE、XBOXKRNL、LIBCPMT 均为 `2.0.6534.16385`；XMEDIA `...16388`；`MDISC 2.0.6534.8193`（多碟支持库，双碟游戏才需要）。
* 导入库只有 `xam.xex` 与 `xboxkrnl.exe`。
* 分级：ESRB `0xFF`（未分级，PAL 盘正常）；PEGI 0x0D、PEGI-FI 0x0C、PEGI-PT 0x0D、PEGI-UK 0x0D、OFLC-NZ 0x04、KMRB 0x02、巴西 0x02。
* 两个 media id 都写在每个可执行文件里，游戏靠它识别换碟。
* 校验和 `0x00AE6EBB`，时间戳 `0x48744044`；按 UTC 读是 2008-07-09 04:36:20，晚于母盘时间；按日本时间读约早一小时，时间顺序更合理。XEX 时间戳的时区没有可靠文档，所以这只是推断。

## 4. XDBF：标题元数据

每部 Xbox 360 作品都在可执行文件的资源段里嵌一个 XDBF 数据库，仪表盘用它显示游戏名、图标与成就列表。

* 位置由 XEX 的 `RESOURCE_INFO` 可选头给出（虚拟地址 + 大小，减镜像基址得偏移）。本作：资源 `535107DB` 在 `0x82AB0000`，159 023 字节，基址 `0x82000000` → `default.exe` 的 `0xAB0000`。
* 容器：`XDBF` 魔数、版本、条目表容量/已用、空闲表容量/已用；数据区起点是 `0x18 + 条目表容量 * 18 + 空闲表容量 * 8`，**所有条目偏移都相对数据区起点**，不是相对文件。
* 条目 18 字节：命名空间、8 字节 id、4 字节偏移、4 字节长度。命名空间 1 = 元数据表（id 低 32 位是 FourCC）、2 = PNG 图像（`0x8000` 是标题图标）、3 = 字符串表（id 是语言 id）。
* `XSTR` 字符串表：UTF-8（不是 UTF-16，对那个年代的微软格式值得一提）。
* `XACH` 成就表：每条 36 字节；**Gamerscore 是 16 位**——按 u16 读，50 个值正好加出 1 000，按 u32 读则不然。

本作内容：25 个条目（11 个元数据表、12 个 PNG、2 个字符串表）。只发行 **2 种语言**（英语 id 1、日语 id 2），各 **317 条**字符串。成就 **50 条、总 1 000G**，从 1G（`Seraphic Gatekeeper`）到 50G（`Compulsive`）；解锁前后两段描述都存，所以未解锁文本也能恢复。

## 5. 相关工具

```
python tools/xex.py  info    default.xex
python tools/xex.py  extract default.xex default.exe
python tools/rtti.py groups  default.exe
python tools/rtti.py list    default.exe --filter "Aska::"
python tools/xdbf.py achievements default.exe
python tools/xdbf.py images  default.exe out/
```
