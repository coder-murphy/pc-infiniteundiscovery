# 04 战斗系统

## 1. 规模

RTTI 里 `Btl…` 类型 **342** 个，另有 `BtlShootCallback_…` **47** 个、`BtlSigCallBack_…` **26** 个。战斗是除游戏侧 `C…` 类之外最大的子系统。

## 2. 设计：模板化的弹道回调

核心模式是**以弹体类 + 数字变体为模板参数的编译期回调**：

```
BtlShootCallback_StraightMove<BtlArrowObject, 13>
BtlShootCallback_ParabolaMove<BtlCollisionEffectObject, 1>
BtlShootCallback_HomingMove<BtlEffCol_DivideSet, 1>
BtlShootCallback_DefaultArrow_typeA<BtlArrowObject, 8>
BtlShootCallback_DragonFirePiller<BtlCollisionEffectObject>
```

可以读出的模型：

* 弹道运动模式（直线 `StraightMove`、抛物线 `ParabolaMove`、追踪 `HomingMove`）是**模板**；
* 弹体类型（`BtlArrowObject` 箭、`BtlCollisionEffectObject` 碰撞特效体、`BtlEffCol_DivideSet` 分裂特效体）也是模板参数；
* 最后的数字是变体编号，用来区分同一组合下的不同配置。

组合在**编译期**实例化，而不是运行期配置。因此游戏用到的每一种"运动 × 弹体 × 变体"都会生成一个独立类型——这正是 342 个类型的主要来源，也说明战斗表现是高度手工调校的，而非通用系统上的参数表。

## 3. 角色专属攻击与内部名单

攻击/弹体以角色命名，因此从类型名恢复出一份内部角色与技能清单：

```
Btl_AYA_Sp10Collision          BtlArrow_AYA_Blitz
BtlShootCallback_EUGUNE_RockThrow
BtlShootCallback_MIRUCE_Page
BtlShootCallback_StraightMove_KOMAC
Btl_SEIRYU_FireBall
LUKA_FamiliarSpiritObject
CLichSkeltonEffect             （原文拼写如此）
```

可识别的角色名：**AYA、EUGUNE、MIRUCE、KOMAC、SEIRYU、LUKA**，以及怪物 `LichSkelton`。`Sp10` 一类后缀像是技能槽编号（Special 10）；`FamiliarSpiritObject` 说明 LUKA 有"使魔/精灵"类召唤物。

这是从代码名反推内容清单的典型案例：**二进制里的类名，就是游戏内部的技能与角色表**。

## 4. 战斗信号

`BtlSigCallBack_…` 26 个类型是战斗信号回调。与"弹道回调"不同，它们响应的是战斗事件（命中、死亡、状态变化等），属于事件驱动的一层。具体信号枚举与触发条件尚未从名字中完整恢复。

## 5. 与场景脚本的分工

* 战斗系统（`Btl…`）负责弹体、命中、特效、技能与角色行为；
* 场景脚本（`SCE-`，见 [08](08-场景资产格式.md)）负责场景里生成谁、站在哪、挂哪根骨头、配哪盏灯；
* AI（见 [03](03-AI系统.md)）负责在战斗/警戒/逃跑状态间切换，并用导航网格移动。

三者通过对象与信号交互，但具体调用链未反编译。

## 6. 这套系统"能读出什么、不能读出什么"

| 能读出 | 不能读出 |
| --- | --- |
| 战斗类型数量与命名体系 | 伤害公式、命中判定 |
| 弹道模式 × 弹体 × 变体的组合方式 | 每个变体的具体参数 |
| 角色/技能/召唤物的内部名单 | 技能数值、冷却、消耗 |
| 信号回调的存在与分组 | 信号枚举与触发顺序 |
| 编译期组合的设计取向 | 运行期数据表（若有） |

换句话说，**结构可读，数值与逻辑不可读**。这与整个仓库的边界一致：RTTI 给名字，不给代码。
