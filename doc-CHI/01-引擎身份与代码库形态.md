# 01 引擎身份与代码库形态

## 1. 游戏与引擎

* 游戏：**Infinite Undiscovery**，tri-Ace 开发、Square Enix 发行，Xbox 360，2008 年。欧版光盘母盘制作于 2008-07-08，发行于 2008-09-05。
* 引擎：**ASKA**，据称展开为 "tri-Ace Superlative Knowledge-based Architecture"。公开资料极少，这也是本仓库存在的主要原因。
* 地位：这是 ASKA 的**第一款作品**；此后同一引擎被复用到多部 tri-Ace 作品，跨度一直到 2016 年（详见 [11-跨作品谱系](11-跨作品谱系.md)）。
* 物理载体：两张 XGD2 DVD，全部资产放在四个 `ud1.bin` / `ud2.bin` 容器中；文件系统只有 4 个文件和 1 个目录。详见 [07-资源容器与压缩](07-资源容器与压缩.md)。

## 2. 证据从哪里来

零售 `default.xex` 是一个标准 XEX2 包装的 PE 镜像。解密、解压之后，PE 保留了**完整的 C++ RTTI**：每个多态类型都带一个 `type_descriptor`，里面是 mangled 类型名，因为 `dynamic_cast` 和 `typeid` 在运行时需要它。因此不需要符号表、调试段或 PDB，只靠零售二进制就能还原类清单。

* 工具：`tools/xex.py` 恢复 PE，`tools/rtti.py` 解析 RTTI 并 demangle。
* 规模：**1 740 个不同类型**，其中 13 个候选字符串无法解析。
* 局限：RTTI 只给名字，不给成员、字段偏移、继承关系或调用图。下文的"职责"都是从名字和同一镜像里的字符串读出来的，属于**解读**。

## 3. 代码库形态

| 分组 | 类型数 | 含义 |
| --- | ---: | --- |
| `C…` | 751 | 游戏侧类，匈牙利式 `C` 前缀 |
| `Btl…` | 342 | 战斗系统 |
| `AI…` | 138 | AI 框架 |
| `AIBehavior_…` | 94 | 单个 AI 行为 |
| `Aska::` | 63 | 引擎本体命名空间 |
| `BtlShootCallback_…` | 47 | 弹道行为回调 |
| `AIFsm_…` | 33 | AI 状态机 |
| `BtlSigCallBack_…` | 26 | 战斗信号回调 |
| `CAI…` | 20 | AI 支持类 |
| `std::` | 9 | 标准库 |

这个分布本身就是一条结论：**引擎边界很薄**。`Aska::` 只有 63 个类型，且只装引擎服务——任务、内存、资源、渲染、相机、碰撞、物理；所有游戏相关内容都在全局命名空间里用匈牙利前缀。这说明 ASKA 在设计上就是给多个项目复用的，游戏代码则保持分离。

## 4. `Aska::` 命名空间的完整清单

### 应用与调度

```
Aska::App   Aska::Task   Aska::FiberTask   Aska::Thread
Aska::MemoryManager
```

纤程与线程同时存在，暗示在 Xbox 360 硬件线程之上还有一层协作式任务调度。另有一个字符串直接点名工作线程：`Aska::ObjectManagerWorkerThread(%d)`。

### 资源

```
Aska::ResourceManager
Aska::ResourceManager::LoadNotify
Aska::ResourceManager::IntermediateLoadNotify
Aska::ResourceManager::DecompressNotify
```

三段独立通知——加载、中间加载、解压——说明是带进度回调的异步流式加载。`DecompressNotify` 正好对应容器里的 SLZ 压缩块。

### 文件处理器

```
Aska::AofHandler   Aska::DirectAofHandler   Aska::AofObject
Aska::AsfHandler
Aska::AcfPrimitiveData_capsule / _cube / _sphere
```

`A…F` 三字母文件族：**AOF** 对象、**ASF** 场景、**ACF** 碰撞。ACF 的三种碰撞体——胶囊、立方体、球——在二进制里就已经点名，后来在光盘数据中被证实。

### 渲染

```
Aska::RenderPassManager      Aska::RenderPassManagerList
Aska::RenderableObject       Aska::RenderablePrimitive
Aska::Primitive              Aska::PrimitiveBufferXe
Aska::ShadowManager          Aska::FrustumObject
Aska::TextureHandler         Aska::ITextureHandler
Aska::TextureModifier        Aska::TextureModifierManager
```

`PrimitiveBufferXe` 的 `Xe` 指 Xenos，是本仓库唯一一个把主机平台写进类名的地方。

### 后处理

```
Aska::BackBufferEffect            Aska::CameraFilter
Aska::BrightnessContrastFilter    Aska::MonotoneFilter
Aska::FramePersistanceEffect      Aska::CrossFader
```

`FramePersistanceEffect` 在零售二进制里就是拼错的（Persistance），属于"没人预料会被读"的遗留细节。

### 相机、动画、物理

```
Aska::Camera   Aska::CameraSynchronizer   Aska::Camera::AFPoint
Aska::Joint    Aska::HierarchicalObject   Aska::HierarchicalObjectContainer
Aska::IAnimatable   Aska::AnimatableLinkElement   Aska::AimingObject
Aska::Dynamics   Aska::DynamicsForceEmitter
Aska::DynamicsWorldWind    ::_WorldWind
Aska::DynamicsOmniWind     ::_OmniWind
Aska::DynamicsCircleWind   ::_CircleWind
Aska::CollisionHandler   Aska::ILandscapeConstraint
```

三种风场——全局、全向点源、圆形——各自带一个嵌套实现结构。对 2008 年的作品来说这是一笔不小的投入，也与游戏大量使用布料和植被摆动的观感吻合。

### 容器库

```
Aska::TArray<T, N>   Aska::TList<T>   Aska::TSmartPointer<N>
Aska::List   Aska::LinkElement   Aska::INotify
```

自研容器库，整个二进制里 `std::` 只出现 9 个类型——那个年代的主机引擎希望自己掌控内存分配，这是典型做法。

## 5. 平台与构建

| 项 | 值 |
| --- | --- |
| CPU / GPU | PowerPC / Xenos，大端 |
| XDK | **6534**，2007 年 11 月版 |
| 静态库 | XAPILIB、D3D9、D3DX9、XGRAPHC、XMEDIA、XAUD 等，全部来自同一 SDK |
| 镜像大小 / 装载地址 | `0xAE0000` / `0x82000000` |
| 入口点 | `0x821CBA90` |
| 区域 | `0x00FF0000`，PAL |
| Title ID | `0x535107DB`（高半字 ASCII `SQ`，Square Enix） |
| 压缩 | basic（两段 data/zero 描述），不是 LZX |
| 导入库 | 只有 `xam.xex` 与 `xboxkrnl.exe` |

两张光盘的 `default.xex` 大小相同，但**不是逐字节相同**：差异集中在安全信息（AES 会话密钥与签名）、多碟头（碟号 1/2）、16 字节 media id，以及整段加密镜像体。头字段、段布局与总大小都一致，因此最合理的解释是同一程序用不同的每碟会话密钥加密；这一点在真正解密后才算定论。细节见 [09-可执行文件与元数据](09-可执行文件与元数据.md)。

## 6. 遗留字符串

只有"没人预料会被读"才会留下的东西：

```
weirdness: global texture (%d) not FOUND!
could not allocate global texture, id=%d
TextureStage %d misses DCLPT
Assertion failed: %s (%s:%u)
```

以及来自标题元数据的一句宣传语：`Tri-Ace presents an exciting new RPG for the Xbox 360!`。

## 7. 这一章不能告诉你什么

RTTI 给的是类型**名字**，不是布局、成员、继承或调用图。本章把名字按职责分组，是阅读，不是反编译。要真正证明某个类做什么，需要反汇编并在数据上做对照——本仓库里只有少数几处做到了（例如 `AHSX` 加载器、SLZ 解压器、XCompress 块表等；见 [05](05-渲染与着色.md) 与 [07](07-资源容器与压缩.md)）。
